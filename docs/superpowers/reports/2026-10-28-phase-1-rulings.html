00Where the rulings landed

Most rulings resolved plan-vs-rule tensions in two places: the write path (who may change state, and how) and what each role may see. The rest renumbered migrations, chose libraries, or decided where a feature lives.

in force applied in the branch and still the rule owner applied, but the owner must ratify or reverse it in design §22 superseded replaced by a later ruling on this page

Reading a card: Decision is what the code does now. Why names the rule, spec section or fact that forced it. Cost if wrong is what it takes to undo. Task numbers refer to the phase 1 plan.

01Pre-flight: the plan disagreed with itself

Before Task 1 was dispatched, the whole plan was scanned for pairs of tasks that share a file or an interface. Ten conflicts surfaced. Each was ruled against the plan text that caused it, so no implementer had to guess.

R-01Task 1in force

Skip git init; commit on a branch

Decision
The repo already held the docs on main. Task 1 commits on phase-1-foundation instead of initialising a repo.
Why
Docs must precede code; re-initialising would have discarded them.
Cost if wrong
None.
R-02Task 1 vs 9, 9b, 9c, 15superseded

Rename the migrations that failed the name check

Decision

Why
Rule 34 names the pattern NNNN_<module>_<topic>.sql.
Cost if wrong
None. Superseded by R-11, which dropped letter suffixes entirely.

Decision
The DIAN mod-11 algorithm gives 3. validateTaxId("900373115-3") normalises to 900373115 with check digit 3; the number is stored without the DV.
Why
Spec §5.8a stores the number and the check digit apart; the plan's "6" was a typo that would have poisoned every seed NIT.
Cost if wrong
Every seeded NIT would fail validation.

None.

03The process pipeline

Rule 1 says every state change runs through runProcess. Nine rulings shaped what that pipeline does when a handler refuses, when a caller only wants to validate, and which tables accept writes from nowhere else.

R-22Task 9in force

A handler-thrown ProcessError keeps its code

Decision
The pipeline used to wrap every handler error as handler_failed. Now a ProcessError thrown by the handler propagates with its own code; the transaction still rolls back and denial codes are still audited.
Why
Domain validation (the country pack, duplicates) lives in handlers and must reach the user as invalid_input, not as a server error.
Cost if wrong
None.
R-23Task 13bin force

stage: "gate" | "handler" on every ProcessError

Decision
Refusals raised by the pipeline (entitlement, permission, step-up, not found) carry stage "gate"; anything a handler throws carries "handler" by default.
Why
The importer must stop the whole file when the caller is denied, but treat a per-row forbidden from the party-scope check as one rejected row.
Cost if wrong
A small API addition.
R-24Task 13bin force

dryRun: the full pipeline, always rolled back

Decision
runProcess(deps, caller, id, input, { dryRun: true }) runs every gate and the handler inside a transaction that is always rolled back; it returns the handler's output or throws the same errors; only denials are audited.
Why
The plan asked for "validate and return errors without writing"; reusing the real pipeline keeps validation identical to the real run.
Cost if wrong
Database triggers still fire inside the rolled-back transaction (acceptable).
R-25Task 9bin force

Kernel processes are always entitled

Decision
runProcess skips the entitlement check when def.module === "kernel"; no migration redefines the SQL kernel.entitled.
Why
The kernel is the platform, not something a tenant buys; duplicating a SQL function body across migrations is a maintenance trap.
Cost if wrong
None.
R-26Task 5in force

Denied runs are audited with action denied

Decision
not_entitled, forbidden and step_up_required write an audit row ({code, process_id}) in their own committed transaction; the audit check constraint gained the action.
Why
Design §5.4 and rule 16: a refusal is part of the history.
Cost if wrong
One constraint edit.
R-27Task 12in force

Preference reads bypass the process registry

Decision
readUserPrefs(sql, claims, keys) is a plain RLS-bound read with no audit row; writes stay in kernel.user_prefs.set.
Why
Two audit rows per page load are noise; rule 1 governs state changes, not reads under RLS.
Cost if wrong
None.
R-28Task 12in force

permission: "none" only for user preferences

Decision
defineProcess asserts that a process without a permission check is in module kernel, of kind update or consult, and its id starts with kernel.user_prefs..
Why
A convenience for one feature must not become a hole anyone can use.
Cost if wrong
An allow-list edit.
R-29Task 13in force

A grid read needs the entity's own consult process

Decision
The grid route refuses when <entity>.consult is not granted; five core entities that had no consult process (units, price lists and items, contacts, sequences) gained one.
Why
Rule 13, permission per process and per entity; falling back to any consult process let a category-only role read price lists.
Cost if wrong
Five small processes.
R-30Final reviewin force

SQL hooks refuse with a typed prefix

Decision
A trigger or hook that raises erp:invalid_input:<message> (SQLSTATE P0001) surfaces as invalid_input with that message; anything else stays handler_failed.
Why
A closed ticket's file freeze lives in SQL and the UI must be able to show why it refused.
Cost if wrong
None.

04Tenancy, roles and step-up

Who a caller is, what their roles mean, and how a revoked role stops counting. The last ruling in this group came from the final review and changed every policy in the database with one function.

R-31Task 2in force

Identity tables: DML for members, admin gate on writes

Decision
authenticated keeps grants on roles, memberships and membership roles (processes run as that role), but every write additionally requires kernel.is_company_admin(); per-process permissions sit on top.
Why
Blanket grants let a member self-assign the admin role; rules 1 and 13.
Cost if wrong
A policy to relax.
R-32Task 3in force

A company's audit rows belong to itself

Decision
Audit entries for kernel.companies use company_id = id.
Why
A company admin must be able to see their own company's history; null would have hidden it.
Cost if wrong
One trigger branch.
R-33Task 5in force

Only the service role inserts step-up verifications

Decision
The Task 10 endpoint, after a valid TOTP code, inserts the verification with the service client; authenticated can only read its own rows.
Why
A self-inserted verification would bypass 2FA (the controller's earlier draft had it the other way, and the reviewer was right).
Cost if wrong
None; the endpoint uses the service client by design.
R-34Task 10in force

Login throttling: a distinct 429 and an app-level limiter

Decision
GoTrue's 429 maps to "demasiados intentos" instead of "wrong credentials"; the client IP is forwarded; kernel.auth_attempts adds a per-account limiter (10 per 5 minutes); session cookies are httpOnly; server modules import server-only.
Why
A shared IP bucket locked out whole offices and the error text was misleading.
Cost if wrong
None. The final review later hashed the keys and added a purge.
R-35Task 15superseded

Support visibility: reporter or holder of reply

Decision
With no role keys in the schema, ticket visibility was "reporter, or anyone who may run support.ticket.reply".
Why
Rule 13: roles are admin-created and carry no fixed names.
Cost if wrong
Superseded by R-36 because reporters also need reply.
R-36Task 15owner

The support agent is whoever may close tickets

Decision
Agent marker = kernel.can_run_process('support.ticket.close'); agents see every ticket and internal notes, reporters see their own.
Why
Reporters must be able to reply to their own tickets, so reply cannot mark an agent.
Cost if wrong
A reporter role cannot close its own tickets without becoming an agent.
R-37Task 19owner

Step-up tokens stay single-use

Decision
Each sensitive run consumes one verification; editing a role and its users costs two codes.
Why
The stricter reading of rule 15; whether one verification should cover a 5-minute window is the owner's call.
Cost if wrong
Extra codes for admins until decided.
R-38Task 19in force

One account, one tenant

Decision
kernel.admin.user.create refuses an e-mail already registered under another tenant and never reads or fills that profile; same-tenant users are added without a new invitation.
Why
The review found an admin could pull another tenant's user into their company and see their mobile, photo and MFA state (rules 12, 36).
Cost if wrong
A consultant working for two tenants needs two accounts until multi-tenant users are designed.
R-39Task 19owner

The system admin role has everything, by definition

Decision
kernel.can_run_process short-circuits for company admins and kernel.field_mode returns visible for them; the manifest sync masks confidential fields for every existing non-admin role and grants a module's consults when it is enabled.
Why
Admin grants were a one-time snapshot and a multi-role admin lost sight of masked fields; rules 13 and 14.
Cost if wrong
An admin cannot be restricted (by design); the owner should confirm.
R-40Final reviewowner

Revoked roles stop counting immediately

Decision
Migration 0024 (see the figure). The process context's roleIds also comes from the live function, so custom-field role checks follow a revocation. The kernel system user keeps its claimed admin role only on a service connection.
Why
A removed admin kept admin rights for up to an hour, including step-up-protected writes.
Cost if wrong
One membership lookup per statement; the system-user carve-out is a §22 decision.

06Files and invoice readiness

Attachments decide whether a party can be invoiced, so their write path got the strictest treatment in the branch: writes outside a process are refused by the database itself.

R-48Task 9bin force

Attachments accept writes only from their own processes

Decision
A restrictive policy requires the transaction's erp.audit_process_id to start with kernel.attachment.; later rulings bound columns to processes (remove may touch only removal columns, reorder only order columns) and reused the pattern for saved views, verifiers, support, imports and recommendations.
Why
These rows drive invoice_ready; defence in depth beyond "the schema is not exposed".
Cost if wrong
Tests must go through the processes (they should anyway).
R-49Task 9bin force

Magic bytes before the bucket

Decision
The upload route sniffs PDF and image signatures and refuses a mismatch with the declared type before a byte is stored; the process keeps the declared-type check.
Why
A declared type is a client claim.
Cost if wrong
None.
R-50Task 9bin force

A missing readiness hook is a loud failure

Decision
When files change, the kernel calls <module>.attachments_changed; if the owning module has no such function the trigger raises instead of doing nothing.
Why
Silent drift of invoice_ready is worse than a failed upload. Every module ships the hook (support's is a no-op that also freezes closed tickets).
Cost if wrong
None.
R-51Task 9bin force

Attachment tables carry the standard columns

Decision
kernel.attachments and kernel.required_attachments have created/updated timestamps and actors (uploaded-by may alias them).
Why
Rule 7.
Cost if wrong
None.

R-53Task 16in force

08Imports and exports

R-62Task 13bin force

Import processes belong to the kernel

Decision

Why

R-63Task 13bin force

The route starts the workflow after the process commits

Decision
kernel.import.run inserts a queued row; the web route then starts the durable workflow with { importId, claims }; the workflow creates each row as that caller with origin api; the files are attachments on a kernel.import entity.
Why

R-64Task 13bin force

Per-row idempotency and honest counts

Decision
Each row's create uses the idempotency key import:<importId>:<rowIndex>; rows_ok/rows_failed are persisted after every batch; a failed import keeps its counts.
Why
Design §5.11 and rule 36 "import partial failures": a retried batch must replay, never duplicate or count created rows as rejected.
Cost if wrong
None.
R-65Task 13bowner

A sensitive target stops the import at the first row

Decision
If the entity's create process needs a step-up, the import fails at the first step_up_required with one message and one denial audit rather than one per row.
Why

Cost if wrong
Imports of sensitive entities wait for the decision.
R-66Task 13bin force

Row and column caps after the first sheet loads

Decision

Why

Cost if wrong

R-67Task 13bin force

Never hand the upload to exceljs

Decision
A strict in-house zip reader walks the directory, inflates each part under a hard bound, verifies size and CRC, and rebuilds a fresh stored archive; exceljs loads only that.
Why
Two rounds of mirroring JSZip's quirks (declared sizes, entry counts, offset shifts) still left bypasses; removing the shared parser removes the class.
Cost if wrong
One extra zip write per import.
R-68Task 13bsuperseded

SheetJS if installable, else exceljs

Decision
The implementer found npm's xlsx stuck at 0.18.5 with known CVEs on untrusted input and unable to write dropdowns, so exceljs 4.4 became the library for imports and exports.
Why
The plan named SheetJS; security trumped the plan text.
Cost if wrong
None.
R-69Task 14superseded

Decision

Why

Cost if wrong

09Assistant and AI

Rule 17 says the assistant acts strictly as the user and never writes without a confirmation card. The confirmation card's state machine below is where three rulings and two review rounds converged.

R-74Task 17in force

Compare-and-set confirmations, no held transaction

Decision
