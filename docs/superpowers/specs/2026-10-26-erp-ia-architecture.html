ERP-IA: one process registry, four callers

Every business action is a Process with permissions, audit and events. The screens, the chat agent, the background agents and the scheduler all call the same registry, so anything a person can do by hand the agent can do too, under the same rules.

02 · The contract

One pipeline for every caller

ScreenA form submit or a grid action calls the process from a Server Action.
Chat agentTool list is generated from the registry, filtered by the user's permissions. Writes need an in-chat confirmation.
Background agentRuns as a system identity bounded by the audience role. Proposes actions; the user accepts them.
SchedulerDue tasks run the process as the task owner and deliver the result (email, WhatsApp, in-app).
▼ runProcess(ctx, "sales.order.confirm", input) ▼
1 · Resolve calleruser, agent-as-user, scheduler-as-owner, origin tag
2 · Entitlementis the module or feature enabled for this company?
3 · Permissionrole × process × kind (create, update, delete, consult)
4 · Step-upadmin-listed processes need fresh TOTP or a supervisor's authorization
5 · ValidateZod input schema (the same schema the agent sees)
6 · Transactionhandler writes state, field masks applied on reads
7 · Outboxdomain events written in the same transaction
8 · Auditwho, what, diff, origin, conversation id, causal chain id

Consult-kind processes skip the transaction but keep permission, masking and audit. A new module registers its processes and is immediately usable from the UI, the agent and the scheduler.

03 · Integration

What one confirmed sale sets in motion

Modules never call each other. They emit events; consumers run their own processes; the posting engine turns events into journal entries using templates the country pack seeds.

05 · Security

Seven layers, applied identically to screens, exports and the agent

EntitlementModules, features and limits bought per tenant. A disabled module is invisible to screens, exports and the agent; its data and queued events are kept for re-enabling.
AuthenticationSupabase Auth. TOTP 2FA optional per user, enforceable per role. JWT carries tenant, companies and roles so RLS needs no joins.
Process permissionsprocess_permissions(role, process, kind) with kind = create, update, delete, consult. Checked before any handler runs.
Row Level SecurityEvery table filters by company_id from the JWT, plus ownership predicates a module declares (a rep sees their own opportunities).
Field visibilityfield_permissions(role, entity, field, visible | masked | hidden) enforced in the SELECT views, so the agent and the exports never receive a hidden value.
Step-up authorizationAdmin lists sensitive processes (discounts, voids, period close, payroll run). They require a fresh TOTP or a supervisor's authorization on the same screen or chat.
AuditAppend-only log with diffs, origin, agent conversation id and causal chain id. Row triggers capture direct database edits too.

06 · AI

A chat agent that acts as the user, and background agents that coach

Chat agent tool families

A DurableAgent per turn, in a Workflow, streaming to the panel. Tools are generated, not hand-written.

process.*Every registered process the user may run. Writes render a confirmation card; step-up processes ask for the 2FA code in the chat.
data.queryEntity, filters, sort, group and aggregate over registered fields. No free SQL except for the analyst role, read-only, with timeouts.
forms.createNew custom entity as a real table with fields and layout. Gets grid, RLS, audit and its own processes at once.
reports.createReport definition (source, columns, filters, grouping, chart). Renders through the same grid, so it sorts, filters and exports.
docs.generateTemplate + record to PDF or DOCX in Storage.
sim.runCash-flow projection, pricing and margin what-if, sales goal scenarios, reorder, payroll cost, loan amortization.
messages.sendEmail, WhatsApp, in-app. Always confirmed, always audited.
scheduler.task.*"Every Monday at 5:00 send the sales report" becomes a row the cron tick picks up and runs as me.
help.searchUser guide and process descriptions in pgvector; answers with steps and deep links, or just navigates there.
support.ticket.*Bug or question with auto-captured context: route, last audit entries, console errors.

08 · Delivery

Phases, in dependency order

  1. Foundation. Kernel, core module, grid and exports, auth with MFA, agent chat with consult, help and navigate tools, support tickets.
  2. Order to cash. CRM, sales, invoicing with DIAN e-invoicing, inventory, warehouse, costing, payments, accounting. The flow in section 03 runs end to end.
  3. Procure to pay and money. Purchases, bank reconciliation, finance, fixed assets, scheduler, messaging, first background agents.
  4. People. Timekeeping, payroll with nómina electrónica and PILA.
  5. POS and builders. Offline PWA point of sale, forms and reports created from chat, simulations.
  6. Second country pack. Proves the localization boundary holds.
