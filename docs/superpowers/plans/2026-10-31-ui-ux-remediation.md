## 2. Owner decisions needed (recommendation first)

**Decision status** (the owner edits this line; an executor reads it and never changes it): UX-OD-1 decided 2026-10-31: (a) v5 + Más/Menú · UX-OD-2 decided 2026-10-31: sheet < 768 / overlay 768–1279 / dock ≥ 1280 · UX-OD-3 decided 2026-10-31: sum of top-most rows, server-side · UX-OD-4 decided 2026-10-31: warn, memory only · UX-OD-5 decided 2026-10-31: only `<module>.<noun>.create` · UX-OD-6 decided 2026-10-31: grid default view columns · UX-OD-7 decided 2026-10-31: KPI → filter map (optional `href` on the kernel `Kpi` contract). A decision counts only when it reads `decided <date>: <option>` here and is recorded in the design's §22.21.

- **UX-OD-1 · Compact navigation [v7].** (a, recommended) Without adopting v7: under 1024 px the module items collapse into one "Menú" button that opens a sheet listing Módulos and the active module's items (groups expanded); ≥ 1024 px items that do not fit move to a trailing "Más ▾" menu measured at runtime; global actions (⌘K, theme, bell, Asistente, user) and the company switcher (truncated with full name in its tooltip) are never displaced. (b) Approve shell v7 first and fold this into its OD-5 (rail as a sheet on phones). Either way, recorded as §22.21 since rule 19 describes the top-bar items.
- **UX-OD-2 · Assistant on phones.** Recommended: under 768 px the assistant opens as a full-screen sheet (the §19a "conversation-first" mobile direction) with a visible "Cerrar" control, safe-area insets and `dvh`/visual-viewport sizing for the on-screen keyboard; 768–1279 px it overlays the page instead of pushing it below a minimum main width (proposed 480 px); ≥ 1280 px today's docked 400 px drawer. Changes rule 19's "drawer of 400 px" wording → §22.21.
- **UX-OD-3 · Totals of roll-up columns (accounting owner).** Recommended: a field declares `rollup: true` (`period_figure` on the five masters). For such a column the grid footer, selection totals and exports show **no generic sum**; instead the footer shows "Total" computed as the sum over the rows **with no ancestor in the result** (for an unfiltered tree: the roots), computed server-side in the kernel query so it covers all pages, filters and RLS-visible rows; selection totals use the same rule over the selection. Alternative (simpler, first step): roll-up columns show no total at all ("—" with an explanation tooltip). Leaf-only sums are rejected: they hide postings that a filter excluded.
- **UX-OD-4 · Dirty-form policy.** Recommended: in-memory only (no storage of form values, so no masking risk); `beforeunload` native prompt on refresh/close of the browser tab; an app dialog "Guardar · Descartar · Cancelar" on closing an ERP tab, switching module/route from a dirty form, switching company and signing out; a "Sin guardar" dot on the tab and the form footer.
- **UX-OD-5 · Create commands.** Recommended: ⌘K offers only processes named `<module>.<noun>.create`; others (`from_template`, `reverse`, `opening.create`) stay on their screens. Alternative: keep them with their own label keys (`nav.create.accounting.entry.from_template` → "Crear comprobante desde plantilla").
- **UX-OD-6 · Assistant result columns.** Recommended: show the entity's grid default view columns (identity, display field, up to 6 visible), with "Ver todas las columnas" expanding in place and "Abrir como grid" unchanged; enum values and refs through the grid's formatters.
- **UX-OD-7 · KPI drill-downs.** Each KPI links to its grid with the KPI's filter (e.g. "Borradores" → `/accounting/entries?status=draft`); needs the owner's list of KPI → filter. Not started without it.
